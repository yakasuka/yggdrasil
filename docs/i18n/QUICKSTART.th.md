## วิธีที่แนะนำ: Config Builder

เปิด [Config Builder](https://yakasuka.github.io/yggdrasil/config-builder/) แล้วทำตามห้าขั้นตอน:

1. **แหล่งสมัครสมาชิก.** ป้อนชื่อผู้ให้บริการ (airport) และการสมัครสมาชิกแบบ YAML, Base64 หรือลิงก์โหนดทั่วไป ระบบจะแยกวิเคราะห์โหนดและข้อมูลปริมาณการใช้งานที่ผู้ให้บริการรายงาน
2. **โหนดตามภูมิภาค.** เฉพาะภูมิภาคที่มีอยู่จริงในการสมัครสมาชิกเท่านั้นที่จะแสดง เลือกว่าจะเก็บโหนดใดบ้าง
3. **กลยุทธ์โหนด.** เก็บกลยุทธ์อัตโนมัติที่ต้องการ ส่วนขาออกเริ่มต้นคือการเลือกด้วยตนเอง
4. **การกำหนดเส้นทางแอป.** แอปทั้งหมดเปิดใช้งานและผ่าน proxy ตามค่าเริ่มต้น เมื่อจำเป็น ให้กำหนดภูมิภาคที่เก็บไว้, Direct หรือ Reject ให้กับแต่ละแอป
5. **ยืนยันขั้นสุดท้าย.** ดูตัวอย่างการกำหนดค่า ดาวน์โหลดไฟล์ `name-ratatoskr.yaml` หรือสร้างลิงก์สมัครสมาชิกถาวร

การสมัครสมาชิกยอมรับ YAML, Base64 และลิงก์โหนดทั่วไป ข้อมูลปริมาณการใช้งานมาจาก `Subscription-Userinfo` ของผู้ให้บริการ การตรวจสอบความหน่วงแบบเลือกได้จะวัดเวลาการสร้างการเชื่อมต่อ TCP — ไม่ใช่ ICMP ping หรือความหน่วงของ proxy แบบเต็ม

## วิธีด้วยตนเอง: ใช้แม่แบบโดยตรง

1. ดาวน์โหลด [ratatoskr-template.yaml](https://github.com/yakasuka/yggdrasil/releases/latest/download/ratatoskr-template.yaml)
2. จัดการ `proxy-providers` / `proxies` ของคุณเองด้วยโหนดจากการสมัครสมาชิก
3. ตรวจสอบว่าไคลเอนต์มีข้อมูล GeoSite / GeoIP ที่อ้างถึง
4. นำเข้าไปยังไคลเอนต์ที่รองรับ Mihomo เลือกขาออกตามแอปหรือภูมิภาค แล้วรันการทดสอบความหน่วงอีกครั้ง

## พอร์ต

| การกำหนดค่า | HTTP | SOCKS5 |
| :--- | :--- | :--- |
| แม่แบบด้วยตนเอง | `7890` | `7891` |
| ผลลัพธ์จาก Config Builder | `7890` | `7890` |

Config Builder ใช้พอร์ตผสม (mixed port) และอนุญาตให้ปรับแต่งได้ ควรเก็บ URL การสมัครสมาชิกส่วนตัว, ข้อมูลรับรองโหนด และโทเค็นการเข้าถึงไว้ในเวิร์กโฟลว์ภายในหรือส่วนตัว

## การติดตั้งใช้งาน

Config Builder และบริการสมัครสมาชิกติดตั้งใช้งานร่วมกันบน Cloudflare Pages ดู [คู่มือการติดตั้งใช้งาน](../../config-builder/docs/DEPLOYMENT.md) และ [แผนภาพการทำงาน](../../config-builder/docs/IMPLEMENTATION.md)
