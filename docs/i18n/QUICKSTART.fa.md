## روش توصیه شده: Config Builder

[Config Builder](https://yakasuka.github.io/yggdrasil/config-builder/) را باز کنید و پنج مرحله را دنبال کنید:

1. **منبع اشتراک.** نام ارائه دهنده (airport) و یک اشتراک YAML، Base64 یا لینک نود رایج را وارد کنید. نودها و اطلاعات ترافیک گزارش شده توسط ارائه دهنده تجزیه می شوند.
2. **نودهای منطقه.** تنها مناطقی که واقعاً در اشتراک وجود دارند نمایش داده می شوند؛ انتخاب کنید که کدام نودها حفظ شوند.
3. **استراتژی های نود.** استراتژی های خودکار مورد نیاز خود را حفظ کنید؛ خروجی پیش فرض انتخاب دستی است.
4. **مسیریابی برنامه.** تمام برنامه ها به طور پیش فرض فعال و تحت پروکسی هستند. در صورت نیاز، برای هر برنامه یک منطقهٔ حفظشده، Direct یا Reject تعیین کنید.
5. **تأیید نهایی.** پیکربندی را پیش نمایش کنید، فایل `name-ratatoskr.yaml` را دانلود نمایید یا یک لینک اشتراک دائمی ایجاد کنید.

اشتراک ها YAML، Base64 و لینک های نود رایج را می پذیرند. داده های ترافیک از `Subscription-Userinfo` ارائه دهنده می آیند. بررسی تأخیر اختیاری، زمان برقراری اتصال TCP را اندازه گیری می کند — نه ICMP ping و نه تأخیر کامل پروکسی.

## روش دستی: استفاده مستقیم از الگو

1. فایل [ratatoskr-template.yaml](https://github.com/yakasuka/yggdrasil/releases/latest/download/ratatoskr-template.yaml) را دانلود کنید.
2. `proxy-providers` / `proxies` خود را با نودهای اشتراک به صورت محلی نگهداری کنید.
3. اطمینان حاصل کنید که کلاینت داده های GeoSite / GeoIP مورد ارجاع را دارد.
4. وارد یک کلاینت سازگار با Mihomo شوید، خروجی را برای هر برنامه یا منطقه انتخاب کرده و آزمون های تأخیر را دوباره اجرا نمایید.

## پورت ها

| پیکربندی | HTTP | SOCKS5 |
| :--- | :--- | :--- |
| الگوی دستی | `7890` | `7891` |
| خروجی Config Builder | `7890` | `7890` |

Config Builder از پورت ترکیبی (mixed port) استفاده می کند و امکان سفارشی سازی را فراهم می نماید. آدرس های اشتراک شخصی، اعتبارنامه های نود و توکن های دسترسی را در یک جریان کاری محلی یا خصوصی نگهداری کنید.
