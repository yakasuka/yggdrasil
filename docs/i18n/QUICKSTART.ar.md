## الطريقة الموصى بها: Config Builder

افتح [Config Builder](https://yakasuka.github.io/yggdrasil/config-builder/) واتبع خمس خطوات:

1. **مصدر الاشتراك.** أدخل اسم مزوّد الخدمة واشتراكًا بصيغة YAML أو Base64 أو روابط عُقد شائعة؛ سيتم تحليل العُقد ومعلومات الحركة التي يبلغ عنها المزوّد.
2. **عُقد المناطق.** تُعرض فقط المناطق الموجودة فعليًا في الاشتراك؛ اختر العُقد التي تريد الاحتفاظ بها.
3. **استراتيجيات العُقد.** احتفظ بالاستراتيجيات التلقائية التي تحتاجها؛ الخروج الافتراضي هو الاختيار اليدوي.
4. **توجيه التطبيقات.** جميع التطبيقات مُفعّلة وتمر عبر proxy افتراضيًا. خصّص لكل تطبيق منطقة محتفظ بها أو Direct أو Reject حسب الحاجة.
5. **التأكيد النهائي.** عاين التهيئة، ونزّل `name-ratatoskr.yaml`، أو أنشئ رابط اشتراك دائمًا.

تقبل الاشتراكات صيغ YAML وBase64 وروابط العُقد الشائعة. تأتي بيانات الحركة من `Subscription-Userinfo` لدى المزوّد. تقيس فحوصات التأخير الاختيارية زمن إنشاء اتصال TCP — وليس ping الخاص بـ ICMP ولا زمن proxy الكامل.

## يدويًا: استخدام القالب مباشرة

1. نزّل [ratatoskr-template.yaml](https://github.com/yakasuka/yggdrasil/releases/latest/download/ratatoskr-template.yaml).
2. احتفظ بملفات `proxy-providers` / `proxies` الخاصة بك مع عُقد الاشتراك.
3. تأكد من أن العميل يتوفر على بيانات GeoSite / GeoIP المشار إليها.
4. استورد التهيئة في عميل متوافق مع Mihomo، واختر خروجًا لكل تطبيق أو منطقة، وأعد تشغيل اختبارات التأخير.

| :--- | :--- | :--- |
| القالب اليدوي | `7890` | `7891` |

تستخدم أداة Config Builder منفذًا مختلطًا وتسمح بتخصيصه. احتفظ بعناوين الاشتراك الشخصية وبيانات اعتماد العُقد ورموز الوصول في سير عمل محلي أو خاص.
