## 設定が小さいのに、なぜ多くのサービスをカバーできるのですか？

Ratatoskr は Geo データの分類を参照するだけで、具体的なドメインと IP のデータはデータベースが保持します。設定には分類への参照、マッチング順序、出口の編成のみを残しています。Geo データベースは引き続きクライアント側で読み込み・更新する必要があります。

## ある YAML を入手すれば、どのクライアントでも使えますか？

設定は Mihomo を対象としています。クライアントは関連する構文に対応し、参照先の Geo 分類を備えている必要があります。DNS、TUN などのネットワーク乗っ取り機能は、選択したテンプレートとデバイス環境によって異なります。

## 今後のメンテナンスで、毎回すべての設定を書き直す必要がありますか？

Geo データの分類、補助ルールソース、ノードサブスクリプション、出口戦略はそれぞれ独立して管理されています。クライアントの仕組みに従ってデータを更新し、必要なときだけ該当するルールやプロキシグループを調整します。分類名と参照は有効なまま保つ必要があります。

## 広告ブロックルールはどのように更新されますか？

AdGuard デスクトップルールは、GitHub Actions が毎日公式アップストリームをプローブし、内容が変化したときだけルールファイルを取得・更新します。低リソース運用の遅延更新方式に従っています。

## Config Builder とメイン設定はどのような関係ですか？

Config Builder（Yggdrasil アプリケーション）は Ratatoskr テンプレート内のアプリケーション、地域、戦略の定義を読み取り、Web 画面での選択に従って個人設定を組み立てます。一方は整理と生成を担い、もう一方は実際の分流とノード戦略を定義します。
