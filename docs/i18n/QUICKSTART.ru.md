## Рекомендуемый способ: Config Builder

Откройте [Config Builder](https://yakasuka.github.io/yggdrasil/config-builder/) и выполните пять шагов:

1. **Источник подписки.** Укажите название провайдера и подписку в формате YAML, Base64 или со ссылками на узлы; узлы и информация о трафике от провайдера будут разобраны.
2. **Узлы по регионам.** Отображаются только регионы, действительно присутствующие в подписке; выберите, какие узлы оставить.
3. **Стратегии узлов.** Оставьте нужные автоматические стратегии; стратегия выхода по умолчанию — ручной выбор.
4. **Маршрутизация приложений.** Все приложения включены и проходят через прокси по умолчанию. Назначьте каждому приложению сохранённый регион, Direct или Reject по необходимости.
5. **Финальное подтверждение.** Предпросмотр конфигурации, скачивание `name-ratatoskr.yaml` или создание постоянной ссылки на подписку.

Подписки принимают YAML, Base64 и ссылки на узлы. Данные о трафике берутся из `Subscription-Userinfo` провайдера. Дополнительные проверки задержки измеряют время установления TCP-соединения, а не ICMP ping или полную задержку прокси.

## Вручную: прямое использование шаблона

1. Скачайте [ratatoskr-template.yaml](https://github.com/yakasuka/yggdrasil/releases/latest/download/ratatoskr-template.yaml).
2. Самостоятельно поддерживайте `proxy-providers` / `proxies` с узлами из подписки.
3. Убедитесь, что у клиента есть ссылка на данные GeoSite / GeoIP.
4. Импортируйте в клиент, совместимый с Mihomo, выберите выход для каждого приложения или региона и снова запустите тесты задержки.

## Порты

| Конфигурация | HTTP | SOCKS5 |
| :--- | :--- | :--- |
| Ручной шаблон | `7890` | `7891` |
| Результат Config Builder | `7890` | `7890` |

Config Builder использует смешанный порт и допускает его настройку. Личные URL подписок, учётные данные узлов и токены доступа храните в локальном или приватном рабочем процессе.

## Развёртывание

Config Builder и сервис подписок развёртываются вместе на Cloudflare Pages. См. [руководство по развёртыванию](../../config-builder/docs/DEPLOYMENT.md) и [карту реализации](../../config-builder/docs/IMPLEMENTATION.md).
