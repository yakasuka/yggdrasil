## 설정은 이렇게 작은데 많은 서비스를 어떻게 커버하나요?

Ratatoskr는 Geo 데이터 분류를 참조할 뿐, 실제 도메인과 IP 데이터는 데이터베이스가 담습니다. 설정에는 분류 참조, 매칭 순서, 아웃바운드 구성만 남아 있습니다. Geo 데이터베이스는 여전히 클라이언트에서 로드하고 업데이트해야 합니다.

## YAML 하나를 받으면 모든 클라이언트에서 사용할 수 있나요?

설정은 Mihomo를 대상으로 합니다. 클라이언트는 관련 구문을 지원하고 참조된 Geo 분류를 포함해야 합니다. DNS, TUN 등 네트워크 인수 기능은 선택한 템플릿과 장비 환경에 따라 달라집니다.

## 유지 관리할 때마다 전체 설정을 다시 작성해야 하나요?

Geo 데이터 분류, 보조 규칙 출처, 노드 구독, 아웃바운드 전략은 각각 따로 관리됩니다. 클라이언트 방식에 따라 데이터를 갱신하고, 필요할 때만 해당 규칙이나 프록시 그룹을 조정하세요. 분류 이름과 참조는 유효한 상태로 유지해야 합니다.

## 광고 차단 규칙은 어떻게 업데이트되나요?

GitHub Actions가 매일 공식 AdGuard 업스트림을 확인하여 내용이 변경된 경우에만 규칙 파일을 가져와 갱신합니다. 낮은 리소스 사용의 지연 업데이트 방식을 따릅니다.

## Config Builder와 메인 설정은 어떤 관계인가요?

Config Builder(Yggdrasil 애플리케이션)는 Ratatoskr 템플릿의 애플리케이션, 지역, 전략 정의를 읽어 웹에서 선택한 내용에 따라 개인 설정을 조립합니다. 하나는 구성하고 생성하며, 다른 하나는 실제 라우팅과 노드 전략을 정의합니다.
