## ทำไมการกำหนดค่าจึงเล็ก แต่ครอบคลุมบริการได้มาก?

Ratatoskr อ้างอิงหมวดหมู่ของข้อมูล Geo ส่วนข้อมูลโดเมนและ IP ที่เจาะจงนั้นอยู่ในฐานข้อมูล การกำหนดค่าเก็บเฉพาะการอ้างอิงหมวดหมู่, ลำดับการจับคู่ และการจัดการขาออก ฐานข้อมูล Geo ยังคงต้องถูกโหลดและอัปเดตโดยไคลเอนต์

## สามารถใช้ YAML เดียวกับไคลเอนต์ทุกตัวได้ไหม?

การกำหนดค่ามีเป้าหมายที่ Mihomo ไคลเอนต์ต้องรองรับไวยากรณ์ที่เกี่ยวข้องและมีหมวดหมู่ Geo ที่อ้างอิง ฟีเจอร์อย่าง DNS, TUN และการเข้าควบคุมเครือข่ายอื่นๆ ขึ้นอยู่กับแม่แบบที่เลือกและสภาพแวดล้อมของอุปกรณ์

## การบำรุงรักษาต้องเขียนการกำหนดค่าใหม่ทั้งหมดทุกครั้งไหม?

หมวดหมู่ Geo, แหล่งกฎเพิ่มเติม, การสมัครสมาชิกโหนด และกลยุทธ์ขาออกได้รับการดูแลแยกกัน ให้อัปเดตข้อมูลผ่านกลไกของไคลเอนต์และปรับกฎหรือกลุ่ม proxy ที่เกี่ยวข้องเฉพาะเมื่อจำเป็น ชื่อและการอ้างอิงหมวดหมู่ต้องยังคงใช้ได้อยู่

## อัปเดตกฎการบล็อกโฆษณาอย่างไร?

GitHub Actions ตรวจสอบต้นทาง AdGuard อย่างเป็นทางการทุกวัน และดาวน์โหลดและอัปเดตไฟล์กฎเฉพาะเมื่อเนื้อหาเปลี่ยนแปลง โดยทำตามแนวทางอัปเดตแบบ lazy ที่ใช้ทรัพยากรต่ำ

## Config Builder กับการกำหนดค่าหลักมีความเกี่ยวข้องอย่างไร?

Config Builder (แอป Yggdrasil) อ่านคำนิยามแอป, ภูมิภาค และกลยุทธ์ในแม่แบบ Ratatoskr แล้วประกอบการกำหนดค่าส่วนบุคคลจากสิ่งที่คุณเลือกบนหน้าเว็บ ฝ่ายหนึ่งจัดระเบียบและสร้าง อีกฝ่ายหนึ่งกำหนดการกำหนดเส้นทางและกลยุทธ์โหนดจริง
